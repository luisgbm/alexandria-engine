# Editorial workflow on staging

Available at https://admin.52-153-234-132.sslip.io/ without a tunnel.
Only alexandria staging is changed; the original website and DNS are unchanged.

## Articles, pages and tags

Use **Novo artigo** or **Nova página**. Pages have stable IDs and their own
permalinks, and use the same HTML editor, uploads, live preview and publishing
validation as articles. Creating a page does not automatically add it to the
main navigation. Article/page kind is fixed after creation.

**Etiquetas** accepts comma-separated tags: up to 30 unique tags, each 1–80
characters. Tags are portable metadata; tag archive pages are not generated.
Title and tag search in the admin ignores accents and case.

Existing published URLs stay locked, including after release rollback.
Generated listing pages allow metadata edits, but retain their automatic HTML
and listing definitions. Their lists are regenerated by the build engine.

## Category management

Expand **Gerenciar categorias** to create categories, rename their display names,
reorder them, or delete unused categories. The slug/identifier is fixed at creation.
Changing a name never rewrites article permalinks or category archive paths.

Deletion is rejected if content (including trash), generated listing definitions,
the original import, or a retained public archive depends on the category.
Reassign content before deleting an unpublished category. Published/historical
categories remain protected: retirement/redirect changes require separate URL
review rather than silently breaking old links. There is no automatic bulk
reassignment or published-category merge in this version.

Category changes are saved in private `content/editorial/site.json`, with prior
catalog versions under `content/editorial/catalog-history/`. They survive service
restarts. The next explicit content publication incorporates the current staged
catalog; edits to unrelated drafts are not promoted. Release rollback restores
the published catalog while keeping staged editorial changes.

## Version history

**Histórico editorial** lists the imported original, where applicable, and all
Alexandria saved versions. Open a version to inspect its HTML. Choosing
**Restaurar como rascunho** creates a new version instead of overwriting history
or publishing immediately. Existing identity, legacy aliases and published URLs
are retained. Save/discard unsaved text before restoring. A stale version in
another tab is rejected with a conflict response.

The separately preserved WordPress raw revision archive remains in private
storage; it is not converted into the Alexandria revision browser in this release.

## Recoverable trash

**Mover para lixeira** hides an item from normal editor lists and disables editing
and publishing it. Choose the **Lixeira** filter, open the item and select
**Restaurar da lixeira** to recover it. Each action creates a new version.
Bodies, images and prior versions are retained. There is no permanent-delete
endpoint or automatic trash purge.

Trash is an editorial action: previously published static pages remain live.
Removing live content needs a separate explicit unpublish/redirect decision.
Trash and revision restore do not switch the active release.

## Storage and controls

Each version now includes `editorial.json` alongside metadata and HTML. The
sidecar records trash status without changing the portable content schema.
Older versions without sidecars remain readable. Version files/directories are
synced before the atomic draft-pointer update.

All endpoints require a valid passkey session; mutations require exact Host,
Origin and CSRF validation. Content changes and catalog changes have optimistic
revision checks and audit events. Recovery and published URLs remain separate
from editorial history.
